Clave y valor.

La lista que aprendiste en la sesión 21 guarda datos en fila y los nombra por su posición: el primero, el segundo, el de en medio. Sirve, pero olvida algo muy humano —los datos rara vez son anónimos. Hoy conoces el diccionario, la estructura que guarda cada dato bajo un nombre que tú eliges. Dejamos de preguntar «¿qué hay en la posición 2?» para preguntar lo que de verdad importa: «¿cuál es la prioridad de esta tarea?».

i.

El dato que se llama por su nombre.

Un diccionario guarda pares clave: valor. La clave es la etiqueta —un texto que tú decides—; el valor es lo que esa etiqueta guarda. Se escribe con llaves { } y se accede por la clave, no por la posición.

Piensa en un diccionario de papel: buscas la palabra «árbol» y a su lado encuentras la definición. No te importa si esa palabra es la número 412 del libro; te importa su nombre. Así trabaja la estructura: le das una clave y te devuelve su valor, al instante.

Una lista te obliga a recordar que el promedio vive en datos[2]. Un diccionario te deja escribir alumno["promedio"] —y el código se lee como una frase.

  • Las claves suelen ser cadenas: "nombre", "edad".
  • Cada clave es única: no se repite dentro del mismo diccionario.
  • El valor puede ser cualquier cosa: texto, número, booleano, incluso otra lista u otro diccionario.
Regla del cuaderno: usa una lista cuando lo que importa es el orden; usa un diccionario cuando lo que importa es el nombre de cada dato.
primer_diccionario.py
# Un alumno descrito con atributos nombrados
alumno = {
    "nombre": "Ana López",
    "edad": 20,
    "promedio": 9.2,
    "inscrito": True,
}

# Accedo por la CLAVE, no por la posicion
print(alumno["nombre"])    # Ana López
print(alumno["promedio"])  # 9.2
ANATOMÍA DE UN PAR
"nombre"→"Ana López"
"edad"→20
"promedio"→9.2

Léelo así: a la izquierda, la etiqueta (la clave); a la derecha, lo que guarda (el valor). Los dos puntos : son el puente entre ambos.

ii.

Variables sueltas contra un diccionario.

Antes describíamos a un alumno con tres o cuatro variables sueltas. Funciona para uno; se vuelve un caos para muchos. El diccionario las reúne bajo un mismo techo y las mantiene juntas.

antes · variables sueltas

Datos que andan dispersos

Cada atributo es una variable independiente. Nada las une: si llega un segundo alumno, necesitas nombre2, edad2, promedio2… y el desorden crece sin freno.

# tres variables que "deberian" ir juntas
nombre = "Ana López"
edad = 20
promedio = 9.2

# ¿y un segundo alumno? nombre2, edad2...
ahora · un diccionario

Datos que viven juntos

Un solo objeto contiene todo lo de un alumno. Lo pasas completo a una función, lo guardas en una lista, lo recorres entero. Los atributos dejan de andar sueltos.

# un objeto con todo dentro
alumno = {
    "nombre": "Ana López",
    "edad": 20,
    "promedio": 9.2,
}
iii.

Crear, leer, cambiar y borrar.

Un diccionario está vivo: nace, crece y mengua. Estas son las cuatro operaciones que harás todos los días —y las tres maneras de recorrerlo de principio a fin.

Para añadir o modificar, asignas a una clave: si no existía, Python la crea; si existía, la sobreescribe. Para borrar, usas del. Y para leer sin riesgo una clave que quizá no esté, usa .get(): en vez de reventar con un KeyError, te devuelve un valor por defecto.

Recorrer un diccionario tiene tres puertas: .keys() te da las claves, .values() los valores, y .items() ambos a la vez —la más útil con diferencia.

Cuidado: pedir alumno["telefono"] de una clave que no existe lanza un KeyError. Si no estás seguro de que esté, usa alumno.get("telefono", "sin dato").
operaciones.py
alumno = {"nombre": "Ana", "edad": 20}

# CREAR / AÑADIR una clave nueva
alumno["carrera"] = "Ingeniería"

# MODIFICAR: la clave ya existe
alumno["edad"] = 21

# LEER con red de seguridad
tel = alumno.get("telefono", "sin dato")
print(tel)            # sin dato

# ELIMINAR un par
del alumno["edad"]

print(alumno)
# {'nombre': 'Ana', 'carrera': 'Ingeniería'}

.items()

Recorre clave y valor a la vez. La forma preferida.

for clave, valor in alumno.items():
    print(clave, "->", valor)
# nombre -> Ana
# edad -> 20

.keys()

Recorre solo las claves —las etiquetas.

for clave in alumno.keys():
    print(clave)
# nombre
# edad

.values()

Recorre solo los valores —el contenido.

for valor in alumno.values():
    print(valor)
# Ana
# 20
iv.

El arreglo de diccionarios.

Aquí se juntan las dos estructuras del curso. Una lista de diccionarios es, ni más ni menos, una tabla: cada diccionario es una fila completa; cada clave, una columna. Así modela datos el mundo real.

Un solo alumno cabe en un diccionario. ¿Un grupo entero? Una lista de diccionarios: cada elemento de la lista es un alumno completo, con todos sus atributos. La lista aporta el orden y el conteo; cada diccionario aporta los nombres de los datos.

Para recorrerla, un solo for te entrega un diccionario por vuelta. Dentro del ciclo accedes a sus campos por clave —limpio, legible, sin trucos de índices.

La gran idea: así viven los datos en bases de datos, en archivos JSON y en casi toda app real. Lo que hoy modelas a mano es el esqueleto de un sistema de verdad.
grupo.py
# Una lista = un grupo; cada dict = un alumno
grupo = [
    {"nombre": "Ana",   "promedio": 9.2},
    {"nombre": "Beto",  "promedio": 7.5},
    {"nombre": "Carla", "promedio": 8.8},
]

# Recorro fila por fila
for alumno in grupo:
    estado = "aprueba" if alumno["promedio"] >= 8 else "revisar"
    print(f"{alumno['nombre']}: {estado}")
# Ana: aprueba
# Beto: revisar
# Carla: aprueba

v.

La pieza clave, en limpio.

Para que no te quedes en blanco frente al esqueleto, aquí está el corazón del gestor: las funciones que agregan, muestran y completan tareas. Estúdialo, entiéndelo y haz tuyo el resto.

gestor_tareas_v2.py — núcleo
tareas = []  # lista de diccionarios

def agregar_tarea():
    titulo = input("Título: ")
    prioridad = input("Prioridad (alta/media/baja): ")
    # cada tarea nace como un diccionario de 3 campos
    tarea = {
        "titulo": titulo,
        "prioridad": prioridad,
        "completada": False,
    }
    tareas.append(tarea)
    print("Tarea agregada.")

def mostrar_tareas():
    if not tareas:
        print("No hay tareas todavía.")
        return
    for i, tarea in enumerate(tareas, start=1):
        marca = "x" if tarea["completada"] else " "
        print(f"[{marca}] {i}. {tarea['titulo']}  ({tarea['prioridad']})")

def completar_tarea():
    numero = int(input("¿Número de la tarea a completar? "))
    if 1 <= numero <= len(tareas):
        tareas[numero - 1]["completada"] = True
        print(f"Tarea {numero} marcada como completada.")
    else:
        print("Ese número no existe.")

Criterios de evaluación

  1. Sin errores de sintaxis ni de ejecución — el gestor corre completo sin reventar.
  2. Lógica correcta — cada tarea es un diccionario con sus tres campos y la lista los conserva juntos.
  3. Funcionamiento óptimo — el menú agrega, muestra y completa tareas; usa .items() o claves al recorrer.
  4. Autenticidad — código escrito por ti, no copiado de un compañero.
