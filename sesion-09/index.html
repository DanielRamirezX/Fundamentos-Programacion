i.

Un camino dentro de otro.

Una decisión anidada es un if dentro de otro if. La segunda pregunta solo tiene sentido si la primera ya resultó verdadera. Así modelas reglas que dependen unas de otras.

Imagina un descuento en una tienda. La regla no es una pregunta, son dos encadenadas: primero, ¿qué tipo de cliente es?; y solo después, según la respuesta, ¿cuánto está comprando?

Cada respuesta abre un nuevo cruce de caminos. La indentación —esos cuatro espacios que ya cuidas— es la que dibuja el árbol: lo que está más adentro, depende de lo de afuera.

  • El if de afuera decide la rama.
  • El if de adentro decide el detalle dentro de esa rama.
  • Si anidas demasiado (4, 5 niveles) el código se vuelve ilegible: ahí conviene aplanar.
Regla del cuaderno: anida cuando una decisión depende de otra. Si las preguntas son independientes, mejor sepáralas o únelas con and.
descuentos.py
# Descuento segun tipo de cliente Y monto
tipo  = input("Cliente (vip/normal): ")
monto = float(input("Monto de compra: "))

if tipo == "vip":
    # dentro de la rama VIP, otra decision
    if monto >= 1000:
        descuento = 0.20
    else:
        descuento = 0.10
else:
    # rama cliente normal, anidada tambien
    if monto >= 1000:
        descuento = 0.05
    else:
        descuento = 0.0

total = monto * (1 - descuento)
print(f"Pagas: ${total:.2f}")
EL ÁRBOL DE DECISIÓN
┌─ ¿tipo == "vip"?
│  ├─ monto >= 1000→ 20% de descuento
│  └─ else→ 10% de descuento
└─ else (normal)
   ├─ monto >= 1000→ 5% de descuento
   └─ else→ sin descuento

Léelo de arriba abajo: primero la rama, después el detalle. Cada sangría es un nivel más adentro del bosque.

ii.

Varias preguntas, una sola respuesta.

A veces no necesitas anidar: necesitas combinar. Los operadores and, or y not tejen varias condiciones en una sola expresión booleana —la herencia directa de la sesión 06.

and exige que todas las condiciones sean verdaderas. or se conforma con que al menos una lo sea. not invierte: vuelve falso lo verdadero y al revés.

Con ellos, dos if anidados a menudo se convierten en uno solo, más corto y más claro. Compara la versión anidada de la izquierda con la compuesta: dicen lo mismo.

Cuidado con el orden: Python evalúa primero not, luego and, y al final or. Ante la duda, usa paréntesis y que se lea solo.
compuestas.py
edad   = int(input("Edad: "))
socio  = input("¿Socio? (s/n): ") == "s"

# and -> deben cumplirse las DOS
if edad >= 18 and socio:
    print("Acceso a la sala VIP")

# or -> basta con UNA
if edad < 12 or edad >= 65:
    print("Entrada con descuento")

# not -> invierte la condicion
if not socio:
    print("Te invitamos a inscribirte")

iii.

El match-case, sin la escalera.

Cuando comparas una misma variable contra muchos valores fijos, el match-case (Python 3.10+) lee mejor que una larga escalera de if-elif-else. Lo conociste en la 08; hoy lo refactorizamos en vivo.

El match toma una expresión y la compara contra cada case. El guion bajo —case _— es el comodín: atrapa cualquier valor no contemplado, igual que el else.

No es magia ni reemplaza al if: si tu condición es un rango (monto > 1000) o una lógica compuesta, el if-elif sigue siendo el rey. El match brilla con menús e igualdades exactas.

  • Un case puede ofrecer varios valores con |: case "s" | "si":
  • El comodín case _ va siempre al final.
  • No hace falta break: Python no se «cae» al siguiente caso como en C.
refactor.py
# ANTES: escalera if-elif-else
if opcion == "1":
    print("Consultar saldo")
elif opcion == "2":
    print("Depositar")
elif opcion == "3":
    print("Retirar")
else:
    print("Opcion no valida")

# DESPUES: el mismo menu con match-case
match opcion:
    case "1":
        print("Consultar saldo")
    case "2":
        print("Depositar")
    case "3":
        print("Retirar")
    case _:
        print("Opcion no valida")

Cuando hay rangos o lógica

Si decides con desigualdades o combinas condiciones con and / or, el if-elif es la herramienta correcta.

  • if monto >= 1000:
  • if edad >= 18 and socio:
  • Decisiones que dependen unas de otras (anidadas).
conviene · match-case

Cuando comparas igualdades

Si una misma variable se compara contra muchos valores exactos —un menú, un código, un día—, el match queda más limpio y legible.

  • match opcion: de un menú
  • case "lun" | "mar": varios valores
  • Catálogos de comandos o respuestas fijas.
