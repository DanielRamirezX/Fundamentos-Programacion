i.

La función, otra vez.

Ya las viste en freeCodeCamp. Aquí las consolidamos: anatomía, return contra print, y por qué importan más de lo que parecen.

Una función es un bloque de código con nombre. Le pasas datos (los parámetros), hace algo con ellos, y te entrega un resultado (el return). Su propósito real no es solo «ahorrar líneas» — es darle nombre a una idea para poder usarla muchas veces.

  • def define la función; el nombre va seguido de paréntesis y dos puntos.
  • Parámetros = lo que la función recibe (variables que solo viven dentro).
  • return = el valor que entrega al terminar. No es lo mismo que print.
  • Todo lo que va indentado debajo del def es el cuerpo.
print vs return: print muestra algo en pantalla y se acabó. return te entrega un valor para seguir trabajando con él. Si la función no devuelve nada, devuelve None.
funciones.py
def area_circulo(radio):
    area = 3.14159 * radio ** 2
    return area

# la función se llama y guardamos el resultado
resultado = area_circulo(5)
print(resultado)   # 78.53975

# versión sin return (devuelve None)
def saludar(nombre):
    print(f"Hola, {nombre}!")

x = saludar("Carlos")
print(x)            # None

El alcance.

Las variables tienen vecindario. Lo global se ve desde cualquier función (las flechas verdes lo muestran). Lo local no sale de su cuarto (las flechas rojas chocan con la pared). Esta regla es la fuente del 30% de los bugs de un principiante.

La casa con cuartos

Global: viaja a cualquier cuarto Local: se queda encerrada

Las constantes.

Variables que no deberían cambiar. Una promesa entre programadores: si la nombras EN_MAYÚSCULAS, nadie la toca.

Python no tiene constantes de verdad. No hay una palabra reservada que impida modificar un valor. Pero existe una convención universal: si nombras una variable con MAYÚSCULAS Y GUIONES BAJOS, le estás diciendo a todo el mundo «no me toques».

  • PI = 3.14159 — una constante
  • IVA_MEXICO = 0.16 — el formato es SCREAMING_SNAKE_CASE
  • MAX_INTENTOS = 3 — claro a primera vista

¿Para qué sirven? Para que no haya números mágicos sueltos por el código. Si ves total * 0.16 nadie sabe qué es ese 0.16. Si ves total * IVA_MEXICO, se explica solo.

Regla del cuaderno: si un valor aparece dos veces en tu programa y nunca cambia, conviértelo en constante. Tu yo del futuro te lo agradecerá.
constantes.py
# ✗ mal: números mágicos sueltos
total = 480
iva = total * 0.16
if intentos > 3:
    print("Bloqueado")


# ✓ bien: constantes con nombre claro
IVA_MEXICO   = 0.16
MAX_INTENTOS = 3

total = 480
iva = total * IVA_MEXICO
if intentos > MAX_INTENTOS:
    print("Bloqueado")

    Cazar bugs.
    
        
    Todos los programadores escriben errores — todos, todo el tiempo. Lo que separa a un principiante de un profesional no es no equivocarse, sino saber encontrar el error rápido. Hoy aprendes a usar el depurador de VS Code (también lo tiene PyCharm), la herramienta que te deja ver tu programa por dentro mientras corre.
    
      
    
    
    

    
    
    
      
    
        
    no corre
    
        
    Error de sintaxis
    
        
    El código no es Python válido. Falta un :, un paréntesis, una comilla. Python ni siquiera intenta ejecutarlo.

    revienta a la mitad
    
        
    Error de ejecución
    
        
    El código corre, pero explota en alguna línea: una variable que no existe, sumar texto con números, dividir entre cero.
    
        NameError · TypeError
      
    
      
    
        
    el más traicionero
    
        
    Error de lógica
    
        
    El código corre sin quejarse... pero hace algo incorrecto. El promedio sale mal, la condición no es la que querías. No hay mensaje de error: solo un resultado equivocado.

     LIVE CODING
    
      
    Debugging en vivo.
    
    
    
    
    
      Te voy a mostrar un programa que no funciona. Juntos lo vamos a depurar: leer el error,
      poner un breakpoint, caminar línea por línea, mirar las variables y corregir. Fíjate en el
      método, no solo en la solución — porque en tu reto vas a hacer esto tú solo.
    
    

    
    
      
    Un programa con tres errores
    
      
    Este código debería calcular el total de una compra con IVA, pero falla. Vamos a
      encontrar los tres bugs uno por uno, usando el depurador.
    
    
    

    
    
      
    1Correr y leer el error
    
      
    
        
    Corremos el programa. Python lanza SyntaxError: expected ':' en la línea del def. Bug 1: falta el dos puntos. Lo agregamos.
    
        
    # ✗ antes
def calcular_total(precio, cantidad)
# ✓ después
def calcular_total(precio, cantidad):
    
      
    
    
    

    
    
      
    2Breakpoint + mirar variables
    
      
    
        
    Corre, pero el total sale rarísimo. Ponemos un breakpoint y miramos: cantidad vale "3" (texto, no número). Bug 2: faltó convertir el input con int().
    
        
    # ✗ cantidad es texto "3"
cantidad = input("¿Cuántos? ")
# ✓ ahora es número 3
cantidad = int(input("¿Cuántos? "))
    
      
    
    
    

    
    
      
    3Cazar el error de lógica
    
      
    
        
    Ya no truena, pero el IVA está mal. En el panel de variables vemos que iva es enorme. Bug 3: multiplicamos por 16 en vez de 0.16. Este es el error traicionero: no da mensaje, solo un número equivocado.
    
        
    # ✗ 16 veces el precio (1600%)
iva = subtotal * 16
# ✓ el 16% correcto
iva = subtotal * 0.16
