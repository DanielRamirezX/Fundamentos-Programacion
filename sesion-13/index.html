Antes del juicio.

i.

Repaso relámpago.

Las tres herramientas con las que vas a armar cualquier problema del examen, una al lado de la otra. Léelas en voz baja: ya las conoces, solo las estamos despertando.

decisión

if · else if · else

principal · C++ 
// elige UN camino entre varios
int edad;
cout << "Tu edad: "; cin >> edad;

if (edad < 13)
    cout << "Nino";
else if (edad < 18)
    cout << "Adolescente";
else
    cout << "Adulto";
# elige UN camino entre varios
edad = int(input("Tu edad: "))

if edad < 13:
    print("Niño")
elif edad < 18:
    print("Adolescente")
else:
    print("Adulto")
El orden importa: tanto C++ como Python prueban de arriba hacia abajo y se quedan con la primera condición verdadera.
repetición · cuenta

for · conteo

principal · C++ 
// repite un número CONOCIDO de veces
int suma = 0;
for (int i = 1; i <= 5; i++)   // 1,2,3,4,5
    suma = suma + i;

cout << "Suma: " << suma;   // Suma: 15
# repite un número CONOCIDO de veces
suma = 0
for i in range(1, 6):   # 1,2,3,4,5
    suma = suma + i

print("Suma:", suma)   # Suma: 15
En C++ el for declara el contador, su condición y su paso; en Python range(a, b) llega hasta b - 1. La variable acumuladora se inicia antes del ciclo.
repetición · condición

while + validación

principal · C++ 
// repite MIENTRAS algo siga siendo cierto
int edad;
cout << "Edad (1-120): "; cin >> edad;

while (edad < 1 || edad > 120) {
    cout << "Dato invalido." << endl;
    cout << "Edad (1-120): "; cin >> edad;
}
cout << "Gracias.";
# repite MIENTRAS algo siga siendo cierto
edad = int(input("Edad (1-120): "))

while edad < 1 or edad > 120:
    print("Dato inválido.")
    edad = int(input("Edad (1-120): "))

print("Gracias.")
El patrón de validación robusta de la sesión 11: vuelve a pedir el dato hasta que sea válido. En C++ el «o» se escribe ||. Cuida no caer en un ciclo infinito.
decisión · casos

switch · case

principal · C++ 
// un valor contra varios casos exactos
char opcion;
cout << "Opcion (a/b/c): "; cin >> opcion;

switch (opcion) {
    case 'a':
        cout << "Elegiste A"; break;
    case 'b':
    case 'c':
        cout << "B o C"; break;
    default:
        cout << "Opcion invalida";
}
# un valor contra varios casos exactos
opcion = input("Opción (a/b/c): ")

match opcion:
    case "a":
        print("Elegiste A")
    case "b" | "c":
        print("B o C")
    case _:
        print("Opción inválida")
El default de C++ (como el case _ de Python) es el comodín: atrapa todo lo que no encajó arriba. En C++ cada case necesita su break.
La gran idea del bimestre: casi cualquier programa útil es una mezcla de pedir un dato, validarlo, decidir y repetir. Si dominas esas cuatro acciones, dominas el examen.
ii.

El simulacro.

Tres problemas tipo examen. Resuélvelos con tiempo medido: 15 minutos cada uno, sin ayuda y sin internet, como el jueves. Entrégalos en C++ (Python opcional como apoyo). Si te atoras, abre la pista — pero solo después de intentarlo de verdad. Al final revisamos juntos una solución de referencia.

Problema 1 Nivel: tibio · ⏱ 15 min

El boleto del cine

Un cine cobra $80 la entrada general. Pide al usuario su edad y aplica el descuento correcto: los menores de 12 y los mayores de 60 pagan media entrada; todos los demás pagan completa. Muestra cuánto debe pagar.

input + int() if / elif / else operadores or
  • Define el precio como una constante (sesión 05)
  • Convierte la edad con int()
  • Combina las dos condiciones con or
  • Imprime el total con print()
Ver pista
La media entrada es PRECIO / 2. La condición del descuento es una sola línea con or: if edad < 12 or edad > 60:. Cuidado con los límites — «menores de 12» es < 12, no <=. El que no entra al if cae al else y paga completo.

Pagas: $80 (entrada completa)
Problema 2 Nivel: templado · ⏱ 15 min

El promedio del grupo

Pide cuántos alumnos hay en un grupo y luego, con un ciclo, lee la calificación de cada uno. Al final muestra el promedio y di si el grupo en conjunto aprobó (promedio ≥ 70) o no. Las calificaciones válidas van de 0 a 100.

for · range() acumulador while · validación if / else
  • Usa un acumulador que empiece en 0
  • Recorre con for i in range(n)
  • Valida cada nota con while (sesión 11)
  • El promedio es suma / n
Ver pista
Antes del ciclo: suma = 0. Dentro del for, pides la nota, la validas con un while que vuelva a preguntar si está fuera de 0–100, y haces suma = suma + nota. Después del ciclo, promedio = suma / n y decides con un if promedio >= 70. Ojo: no dividas dentro del ciclo, solo al terminar.
Corrida esperada
TERMINAL — problema2.py
¿Cuántos alumnos? 3
Nota del alumno 1: 150
Inválida. Debe ir de 0 a 100.
Nota del alumno 1: 80
Nota del alumno 2: 60
Nota del alumno 3: 70
Promedio: 70.0 → APROBADO
Problema 3 Nivel: examen · ⏱ 15 min

El cajero del menú

Programa un menú que se repita hasta que el usuario elija salir. Opciones: 1) saludar, 2) decir si un número es par o impar, 3) contar del 1 al número dado, 4) salir. Cualquier otra cosa es opción inválida. Este es el problema integrador: junta todo.

while True match / if % módulo for break
  • El menú vive dentro de un while True
  • Par o impar se decide con numero % 2 == 0
  • La opción 3 usa un for con range
  • La opción 4 corta el ciclo con break
Ver pista
Estructura: while True: imprime el menú, lee la opción, y úsala en un match o en if/elif/else. El operador módulo % da el residuo: si n % 2 == 0 el número es par. Para «salir», dentro del case "4" pones break y el while termina. Recuerda: lo que input() devuelve es texto — compara con "1" o convierte con int(), pero sé consistente.

iii.

La solución de referencia.

En la revisión guiada resolvemos el Problema 3 juntos en el pizarrón y discutimos alternativas. Aquí queda la versión que comentamos en clase — léela después de intentarlo tú, no antes.

principal · C++
problema3_referencia.cpp
// Problema 3 — El cajero del menú
// Integra: while, if/else if, módulo (%), for y break.
#include <iostream>
#include <string>
using namespace std;

int main() {
    string opcion;
    while (true) {
        cout << "\n--- MENU ---" << endl;
        cout << "1 saludar · 2 par/impar · 3 contar · 4 salir" << endl;
        cout << "Opcion: "; cin >> opcion;

        if (opcion == "1") {
            cout << "¡Hola! Que gusto verte." << endl;
        } else if (opcion == "2") {
            int numero;
            cout << "Numero: "; cin >> numero;
            if (numero % 2 == 0)
                cout << numero << " es par" << endl;
            else
                cout << numero << " es impar" << endl;
        } else if (opcion == "3") {
            int tope;
            cout << "¿Hasta que numero? "; cin >> tope;
            for (int i = 1; i <= tope; i++)
                cout << i << " ";
            cout << endl;            // salto de línea final
        } else if (opcion == "4") {
            cout << "¡Hasta luego!" << endl;
            break;                  // corta el while(true)
        } else {
            cout << "Opcion invalida, intenta de nuevo." << endl;
        }
    }
    return 0;
}
problema3_referencia.py
# Problema 3 — El cajero del menú
# Integra: while, match, módulo (%), for y break.

while True:
    print("\n--- MENÚ ---")
    print("1 saludar · 2 par/impar · 3 contar · 4 salir")
    opcion = input("Opción: ")

    match opcion:
        case "1":
            print("¡Hola! Qué gusto verte.")

        case "2":
            numero = int(input("Número: "))
            if numero % 2 == 0:
                print(numero, "es par")
            else:
                print(numero, "es impar")

        case "3":
            tope = int(input("¿Hasta qué número? "))
            for i in range(1, tope + 1):
                print(i, end=" ")
            print()              # salto de línea final

        case "4":
            print("¡Hasta luego!")
            break             # corta el while True

        case _:
            print("Opción inválida, intenta de nuevo.")
Alternativa válida: en C++ el menú se arma con if · else if (o un switch); en Python lo mismo se logra con match o con if / elif / else. El examen acepta cualquiera de esos caminos: lo que se evalúa es que funcione y esté bien razonado.
iv.

Consejos para el juicio.

El examen no mide qué tan rápido tecleas, sino qué tan claro piensas. Estos seis hábitos te ahorran la mitad de los errores. Léelos esta noche, no mañana.

1

Lee dos veces antes de teclear

Subraya en el enunciado qué entra, qué se procesa y qué debe salir. Es el modelo E → P → S de la primera semana. Un minuto leyendo ahorra diez depurando.

2

Haz tu prueba de escritorio

Antes de correr, recorre el código con un dato de ejemplo en una hoja, anotando cómo cambia cada variable. Así cazas los errores de lógica que no avisan con ningún mensaje.

3

Convierte lo que pides

Recuerda que input() siempre devuelve texto. Si vas a hacer cuentas, envuélvelo con int() o float() — el bug número uno del bimestre.

4

Vigila la indentación

En Python, la sangría es la sintaxis. Una línea mal indentada cambia por completo qué corre dentro de un if o un for. Cuatro espacios, siempre.

5

Corre seguido, no al final

Escribe poco, corre, verifica; escribe poco más, corre. No teclees el programa entero para descubrir al final que truena. El hábito de depuración honesta de la sesión 10.

6

Cuida los bordes del ciclo

El range(1, 6) llega al 5, no al 6. Un while sin línea que cambie su condición es un ciclo infinito. Pregúntate siempre: ¿esto termina?

La trampa frecuente
Cómo evitarla
if edad = 18: — un solo igual
Comparar es ==; un solo = es asignar. Es SyntaxError.
"Total: " + promedio — texto + número
Envuelve el número con str(promedio), o usa comas en print(..., promedio).
elif nota > 70: deja fuera el 70
Si el 70 aprueba, usa >=. Los bordes son donde viven los errores de lógica.
while x < 10: sin tocar x
Dentro del ciclo cambia x (p. ej. x = x + 1) o nunca termina.

Cómo se evalúa

  1. Sin errores de sintaxis ni de ejecución — los tres programas corren completos sin reventar.
  2. Lógica correcta — cada problema hace lo que el enunciado pide, sin errores lógicos en los bordes.
  3. Funcionamiento óptimo — cumple validación, decisión y repetición según corresponda a cada caso.
  4. Autenticidad — resuelto por ti; el simulacro es para detectar tus dudas, no las de otro.
