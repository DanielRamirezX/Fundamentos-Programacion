i.

Sustento teórico: el arte de decidir.

Toda decisión en código tiene la misma anatomía: una condición que resulta verdadera o falsa, y uno o dos caminos posibles. La unidad 5 del temario les da tres nombres: if, if–else e if–else anidados (Templeman, 2018).

5.1 · Condicional simple

if

Solo toma en cuenta la parte positiva de la condición: si es verdadera, ejecuta su bloque; si es falsa, no ocurre nada y el programa sigue de largo. Es el guardia que solo actúa cuando algo pasa.

5.2 · Condicional doble

if – else

Toma en cuenta también la parte negativa de la condición ocupando un else: un camino para el sí y otro para el no. Nunca se ejecutan ambos; nunca se queda callada. Es la estructura que exige esta práctica.

5.3 · Anidados

if dentro de if

Un if–else dentro de otro: la primera decisión abre la puerta y la segunda afina la respuesta. Con ellos distinguiremos, dentro del camino positivo, si la ecuación tiene dos raíces distintas o una sola repetida.

Estructura condicional simple
principal · C++
condicional_simple.cpp
// 5.1 · Solo la parte positiva de la condicion
if (condicion) {
    instruccion1;
    instruccion2;
    instruccion3;
}
// si la condicion es falsa, no ocurre nada
condicional_simple.py
# 5.1 · Solo la parte positiva de la condición
if condicion:
    instruccion1
    instruccion2
    instruccion3
# si la condición es falsa, no ocurre nada
Estructura condicional doble
principal · C++
condicional_doble.cpp
// 5.2 · Tambien la parte negativa, con else
if (condicion) {
    instruccion1;
    instruccion2;
    instruccion3;
}
else {
    instruccion1;
    instruccion2;
}

if condicion:
    instruccion1
    instruccion2
    instruccion3
else:
    instruccion1
    instruccion2

ii.

El problema: la fórmula general.

Una ecuación cuadrática tiene la forma ax² + bx + c = 0. La fórmula general la resuelve siempre… cuando hay solución. Y quien decide si la hay es un solo número escondido bajo la raíz: el discriminante.

Antes de escribir una línea de código, entiende la matemática. La fórmula pide tres coeficientes —a, b y c— y devuelve hasta dos valores de x: uno con el signo + y otro con el signo − antes de la raíz.

El peligro vive dentro de la raíz cuadrada: si b² − 4ac es negativo, no existe raíz real y la fórmula se rompe. Ahí entra la estructura condicional doble: la parte positiva calcula las raíces; la parte negativa lo dice con honestidad.

  • Δ > 0 — dos raíces reales distintas: x₁ y x₂.
  • Δ = 0 — una sola raíz doble: x₁ = x₂.
  • Δ < 0 — sin soluciones reales: el camino del else.
La condición de oro: discriminante >= 0. Verdadera → aplica la fórmula. Falsa → informa que no hay soluciones reales. Esa única pregunta es toda la práctica.
x = −b ± √b² − 4ac 2a
La fórmula general. Lo marcado en rojo es el discriminante (Δ): el número que decide qué rama del if–else se ejecuta.

Un caso más: a = 0

división entre cero

Si a = 0 la ecuación ni siquiera es cuadrática y el denominador 2a vale cero. Un if simple (5.1) al inicio del programa detecta este caso y avisa antes de que la aritmética truene. Los programas de laboratorio también se protegen.

Sube de nivel (5.3 · anidados). Dentro de la rama positiva se esconde un caso especial: cuando el discriminante vale exactamente cero, x₁ y x₂ son el mismo número. Un if–else anidado dentro del camino positivo lo distingue con elegancia: primera decisión, ¿hay raíces?; segunda decisión, ¿son una o dos?

Pruébalo con: a = 1, b = −4, c = 4. El discriminante da 16 − 16 = 0 y tu programa debe responder con una sola raíz doble: x = 2.

cuadratica_anidada.cpp
// 5.3 · la FORMA del anidado — el contenido es tuyo
if (discriminante >= 0) {
    if (/* ¿cuando hay una sola raiz? */) {
        // la raiz doble no necesita sqrt()... ¿por que?
    } else {
        // dos raices distintas: x1 y x2
    }
} else {
    // sin soluciones reales
}

Criterios de evaluación

  1. Código y sintaxis sin errores de compilación — g++ compila a la primera, sin advertencias ignoradas.
  2. Lógica del programa sin errores lógicos — las raíces son las correctas y el else responde cuando debe.
  3. Funcionamiento óptimo — de acuerdo con los requisitos explicados en los requerimientos, con los tres casos de prueba superados.
  4. Autenticidad — código hecho por el alumno; no clones de programas de compañeros.
