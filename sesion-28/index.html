i.

Abramos el examen.

La revisión no es para discutir décimas: es para entender. Recorremos los reactivos donde más se tropezó el grupo y vemos, en código, dónde estaba la trampa. Cada error tiene una lección que vale más que la calificación.

El reactivo que más costó pedía recorrer una lista de diccionarios —alumnos con su promedio— y reportar quién reprobó. Tres líneas, tres tentaciones de error: el tipo del dato, el límite de la condición y el formato de la salida.

A la derecha, la versión correcta: léela de arriba abajo y reconoce todo lo que pusiste a trabajar al mismo tiempo —diccionarios, ciclo for, condición, f-string. Eso es el curso entero condensado en un solo problema.

La revisión bien hecha convierte un error en un recuerdo que no se repite. Por eso hoy hablamos cada respuesta, no solo la calificamos.
principal · C++
reactivo_resuelto.cpp
// Reactivo del final: reportar reprobados
#include <iostream>
#include <vector>
#include <string>
using namespace std;

const int APROBATORIA = 70;

struct Alumno {
    string nombre;
    int promedio;
};

int main() {
    vector<Alumno> alumnos = {
        {"Ana",   92},
        {"Beto",  68},
        {"Carla", 70},
    };

    int reprobados = 0;
    for (Alumno alumno : alumnos) {
        // el limite exacto: 70 SI aprueba
        if (alumno.promedio < APROBATORIA) {
            cout << alumno.nombre << ": reprobado" << endl;
            reprobados++;
        }
    }

    cout << "Total reprobados: " << reprobados << endl;
    return 0;
}
// Beto: reprobado
// Total reprobados: 1

El tropiezo más común · cómo se corrige
tipo
1
Usar <= APROBATORIA dejaba al 70 como reprobado. El límite exacto es <: setenta justo, aprueba.
lógica
2
Olvidar int() al leer del input y comparar texto con número.
TypeError
3
Acceder a la clave con alumno.promedio en vez de alumno["promedio"] —los diccionarios usan corchetes.
AttributeError
4
Inicializar el contador dentro del for: se reseteaba en cada vuelta y siempre daba 1.
lógica
5
Abrir el archivo sin with y no cerrarlo —la lección de la sesión 25 sobre memoria que persiste.
ejecución

La gran lección, otra vez: los errores de sintaxis y de ejecución gritan; los de lógica callan. El programa corre, pero miente. Cazarlos fue el oficio de todo el semestre.

iii.

¿Y ahora, a dónde?

Este curso te dio los cimientos: pensar, decidir, repetir, guardar. Lo que sigue son las casas que se construyen sobre ellos. No empiezas de cero en ninguno —llegas con la mitad del camino andado.

la siguiente materia · #1

Estructuras de Datos

Donde las listas, matrices y diccionarios que ya manejas se vuelven herramientas con nombre propio: pilas, colas, árboles, grafos. Aprenderás no solo a guardar datos, sino a guardarlos bien, para buscarlos rápido.

Tu puente: sesiones 20–24. Listas, búsqueda, orden y diccionarios ya te dejaron en la puerta.

la siguiente materia · #2

Programación Orientada a Objetos

Ya creaste funciones que dividen y vencen; ya modelaste un alumno con un diccionario —y con un struct en C++. La POO (natural en C++) te enseña a juntar esos datos y esas funciones en una sola pieza —la clase— para pensar el software como objetos del mundo real.

Tu puente: sesiones 18, 19 y 24. Funciones y modelado de datos son la antesala de las clases.

por tu cuenta · #3

Un proyecto que te importe

La forma más rápida de no olvidar lo aprendido es usarlo en algo tuyo: un gestor de gastos, un bot pequeño, un juego, una herramienta para una clase. Elige un problema que te incomode y resuélvelo en C++ (o en Python como apoyo, según te acomode). Ahí se vuelve permanente.

Tu puente: todo el curso. Ya tienes con qué; ahora solo falta la idea.

tu memoria · #4

El repositorio de GitHub

No lo abandones. Ese repositorio es la prueba viva de que aprendiste: 28 carpetas con tu propio código. Cuídalo, mejóralo, vuelve a él. Es tu primer renglón de currículum y tu cuaderno para siempre.

Tu puente: cada entregable. Lo construiste sesión a sesión; ahora es tuyo.

La reflexión grupal.

Antes de irnos, tres preguntas en voz alta. No hay respuesta incorrecta —solo la tuya.

¿Qué te llevas?

No el lenguaje, sino la forma de pensar: descomponer un problema grande en pasos pequeños que una máquina pueda obedecer. Eso sirve para programar y para casi todo lo demás.

¿Qué te costó más?

Casi siempre fue lo mismo: confiar en que el error se puede encontrar. El día que dejaste de pelear con el debugger y empezaste a leerlo, el curso cambió.

¿Qué te sirvió del enfoque práctico?

Que no copiaste código de la pantalla: lo escribiste. Cada proyecto guiado, cada plano con pasos en blanco, te obligó a decidir el cómo. Por eso hoy puedes seguir solo.

Criterios de evaluación

  1. Sin errores de sintaxis ni de ejecución — a lo largo del curso, tu código corrió completo sin reventar.
  2. Lógica correcta — tus programas hicieron lo que se pedía, sin errores ocultos.
  3. Funcionamiento óptimo — cumpliste los requisitos de cada práctica y entregable.
  4. Autenticidad — código hecho por ti, sesión a sesión. Esa es la verdadera calificación.
