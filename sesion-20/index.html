5.1 · Fundamentos del diseño modular.

Ningún problema grande se resuelve de un golpe. La estrategia más vieja del oficio es partirlo en problemas pequeños, cada uno fácil de entender y de probar. En programación, cada pedazo se llama función, y a juntar el programa con funciones se le llama diseño modular.

Imagina la aplicación de «Mundo-gráfico» escrita de corrido: cien líneas que abren la ventana, dibujan un círculo, un rectángulo y una línea, luego las mueven, las agrandan y refrescan la pantalla… todo amontonado en un solo bloque. Funciona. Pero si mañana quieres cambiar cómo se dibuja el rectángulo, tienes que leer las cien líneas para hallar dónde tocar. Y si te equivocas, rompes el círculo, que no tenía nada que ver.

Ahora imagina el mismo programa partido en funciones: dibujar_circulo, dibujar_rectangulo, dibujar_linea, mover_derecha, cambiar_tamano. Cada una hace una sola cosa, cabe en la pantalla y se lee como una frase. Cambiar el rectángulo es abrir una sola función. Lo demás ni se entera.

antes · todo amontonado

El bloque monolítico

Un solo muro de 100 líneas. Para entender cómo se dibuja una figura, hay que leerlo todo. Si repites el mismo trazo tres veces, tienes tres lugares que mantener.

// 100 líneas seguidas // abrir... círculo... // rectángulo... línea... // mover... agrandar... // todo en main, sin nombres
después · modular

Funciones con nombre

Cada tarea tiene su nombre y su lugar. El main se vuelve un índice legible que solo llama funciones. Cada pieza se prueba por separado.

dibujar_circulo(...) dibujar_rectangulo(...) dibujar_linea(...) mover_derecha(...) cambiar_tamano(...)
5.1.1

Divide y vencerás

El principio de fondo: parte el problema en subproblemas pequeños, resuelve cada uno por separado y luego únelos. Una figura a la vez; una función a la vez.

5.1.2

Objetivos

Que cada parte tenga una responsabilidad clara, que se entienda sola y que el main solo coordine las piezas sin hacer el trabajo pesado.

5.1.3

Ventajas

Legibilidad (se lee como frases), reutilización (una función escrita una vez, usada muchas) y mantenimiento (cambias una pieza sin romper las demás).

La gran idea: una función es un nombre que le pones a un trozo de trabajo. En vez de repetir o amontonar código, lo encierras, lo bautizas y lo llamas cuando lo necesitas.

5.2 · Manejo de funciones.

Toda función tiene la misma forma. Conócela una vez y las reconocerás todas: el tipo que devuelve, el nombre, los parámetros, el cuerpo y el return. Aquí la desarmamos pieza por pieza.

ANATOMÍA · función en C++
int mover_derecha(int x, int paso) {
      return x + paso;
int
El tipo del dato que la función devolverá. Aquí, un entero.
mover_derecha
El nombre: un verbo claro que dice qué hace, en snake_case.
(int x, int paso)
Los parámetros: los datos que recibe para trabajar. Aquí, dos.
return
Devuelve el resultado a quien la llamó. La función entrega su fruto.
x + paso
El cuerpo: el trabajo en sí; su resultado es lo que se devuelve.

Definir una función no la ejecuta: solo le enseña al programa cómo hacer algo y lo guarda con un nombre. Para que trabaje, hay que llamarla por su nombre y pasarle los argumentos entre paréntesis. Entonces los datos entran por los parámetros, el cuerpo corre, y return entrega el resultado de vuelta.

Definir · una figura con varios parámetros

principal · C++
definir.cpp
// 5.2.2 · VARIOS parametros:
// posicion, tamano y color
void dibujar_circulo(int x, int y, int radio, int color) {
    setcolor(color);      // color del trazo
    circle(x, y, radio);   // dibuja el circulo
}   // void: no devuelve nada, solo dibuja
definir.py
# 5.2.2 · VARIOS parámetros:
# posición, tamaño y color
def dibujar_circulo(x, y, radio, color):
    t.penup(); t.goto(x, y); t.pendown()
    t.color(color)     # color del trazo
    t.circle(radio)    # dibuja el círculo

5.2.1 · Un parámetro

area_circulo(radio)

Recibe un solo dato para trabajar. area_circulo(30) toma el radio y devuelve su área. Una entrada, un resultado.

// una función, un dato de entrada

5.2.2 · Varios parámetros

dibujar_circulo(x, y, radio, color)

Recibe varios datos, separados por comas y en orden. Con ellos, una sola función dibuja círculos en cualquier lugar, tamaño y color.

// una función, muchos datos de entrada
5.2.3

Devolución del resultado: return no es dibujar.

La confusión número uno con las funciones. Dibujar (o imprimir) y return parecen «sacar algo» de la función, pero son cosas distintas: una le habla a la pantalla; la otra le habla al programa.

Dibujar / imprimir · le habla a la pantalla

Pinta algo y se acabó. Es para que tú lo veas. El programa no se queda con ningún valor: si la función es void, no puedes guardar lo que «devuelve».

// sirve para MOSTRAR, no para calcular

return · le habla al programa

Entrega un valor a quien llamó la función. Ese valor se puede guardar, comparar, acumular o pasar a otra función. Es la materia prima con la que el programa sigue trabajando.

// sirve para CALCULAR y seguir usando
principal · C++
dibujar_vs_return.cpp
// ──────── Solo DIBUJA (void): habla a la pantalla ────────
void dibujar_circulo(int x, int y, int radio, int color) {
    setcolor(color);
    circle(x, y, radio);   // pinta y nada mas
}   // void: no entrega ningun valor
// int nueva = dibujar_circulo(...);  →  ERROR: void no devuelve nada


// ──────── DEVUELVE (return): habla al programa ────────
int mover_derecha(int x, int paso) {
    return x + paso;   // entrega la nueva posicion
}

int x = 60;
x = mover_derecha(x, 5);   // x ahora vale 65: lo guardamos
x = mover_derecha(x, 5);   // y otra vez: 70. Podemos seguir calculando
dibujar_vs_return.py
# ──────── Solo DIBUJA: habla a la pantalla ────────
def dibujar_circulo(x, y, radio, color):
    t.penup(); t.goto(x, y); t.pendown()
    t.color(color); t.circle(radio)   # pinta y nada más


# ──────── DEVUELVE (return): habla al programa ────────
def mover_derecha(x, paso):
    return x + paso    # entrega la nueva posición

x = -240
x = mover_derecha(x, 5)   # x avanza y lo guardamos
x = mover_derecha(x, 5)   # podemos seguir calculando
Regla del 5.2.3: si vas a usar el resultado (moverte otra vez, comparar, acumular), usa return. Reserva el dibujo para el momento de mostrar. Así separas la lógica (calcular la posición) de la interfaz (dibujar) — justo lo que pide la práctica.

5.3 · Aplicaciones gráficas.

Hasta hoy, la salida del programa era texto en la terminal. Ahora abrimos una ventana y dibujamos en ella. Con graphics.h (Dev C++) bastan tres órdenes para las tres figuras de «Mundo-gráfico»: circle, rectangle y line.

5.3.1 · dibujar las figuras

principal · C++
figuras.cpp
// abre el lienzo: ancho, alto, titulo
initwindow(600, 400, "Mundo-grafico");

setcolor(GREEN);
circle(150, 200, 60);            // circulo: centro y radio

setcolor(RED);
rectangle(260, 140, 460, 260);   // esquinas: sup-izq, inf-der

setcolor(YELLOW);
line(80, 320, 520, 320);        // linea: de un punto a otro

delay(4000);      // espera 4 segundos
closegraph();     // cierra la ventana
figuras.py
import turtle
t = turtle.Turtle()

t.penup(); t.goto(-150, -60); t.pendown()
t.color("green"); t.circle(60)          # círculo

t.penup(); t.goto(-40, 60); t.pendown()
t.color("red")
for _ in range(2):                       # rectángulo: 4 lados
    t.forward(200); t.right(90)
    t.forward(120); t.right(90)

t.penup(); t.goto(-220, -140); t.pendown()
t.color("orange"); t.goto(220, -140)   # línea

Así se ve la ventana al correr

Mundo-grafico — 600 × 400
Tres funciones, tres figuras. El color es un parámetro más: cámbialo y cambia el trazo.
5.3.1 · también sirve para números: la misma idea dibuja la gráfica de una función matemática. Si recorres los valores de x y para cada uno pones un punto en (x, f(x)), la ventana traza la curva. Un círculo o una parábola: al final, todo es dibujar puntos y líneas con funciones.

5.3.2 · animación básica

principal · C++
animacion.cpp
// mover = borrar, redibujar un poco mas alla, repetir
int x = 60;
for (int i = 0; i < 60; i++) {   // 60 cuadros
    cleardevice();                  // borra el cuadro anterior
    dibujar_circulo(x, 200, 40, GREEN);
    delay(30);                     // 30 ms por cuadro
    x = mover_derecha(x, 5);      // avanza 5 px a la derecha
}
animacion.py
# mover = borrar, redibujar un poco más allá, repetir
x = -240
for i in range(60):        # 60 cuadros
    t.clear()                # borra el cuadro anterior
    dibujar_circulo(x, 0, 40, "green")
    x = mover_derecha(x, 5)   # avanza 5 px a la derecha

El círculo cruza la ventana

animación — cuadro por cuadro
La ilusión del movimiento: borrar, redibujar un poco más a la derecha, esperar. Sesenta veces por segundo, parece que se mueve.

Live coding: armamos «Mundo-gráfico».

Ahora juntamos las tres partes en una sola aplicación modular. La construimos en vivo, en clase, módulo por módulo. En esta página queda el plano: los pasos y las firmas de las funciones, no las respuestas.

Primero acordamos juntos el mapa de módulos (instrucción 1 de la práctica): qué tareas hay, en qué módulo vive cada una y qué función la resuelve. Una vez que el mapa está claro, escribir cada función es casi mecánico. El diseño es el trabajo difícil; el código es la consecuencia.

módulo · lógica

Operaciones con figuras

dibujar_circulo(x, y, radio, color) dibujar_rectangulo(x, y, ancho, alto, color) dibujar_linea(x1, y1, x2, y2, color) mover_derecha(x, paso) → int cambiar_tamano(radio, cuanto) → int

Crear, mover y cambiar de tamaño. Combina funciones de varios parámetros (dibujar) con funciones que devuelven (mover, redimensionar).

módulo · interfaz

Interfaz gráfica

initwindow(ancho, alto, titulo) cleardevice() delay(ms) closegraph()

El lienzo. Abre la ventana, la limpia entre cuadros y la cierra. Es donde las figuras aparecen y se refrescan.

main()

No dibuja ni calcula: coordina. Llama a las figuras, corre el ciclo de animación y espera al usuario. Se lee como un índice de tareas.
