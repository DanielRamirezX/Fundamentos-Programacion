El mapa de lo que entra.

El examen final pesa el 50% del curso y mira hacia atrás todo el semestre, pero con énfasis en el segundo bimestre. Aquí está, sin sorpresas, el territorio que debes dominar. Lo marcado en rojo es lo que más cae.

1er bimestre · base se da por sabido

Fundamentos que ya respiras

  • Variables, tipos y conversiones con int(), float(), str()
  • Entrada y salida: input() y print() con f-strings
  • Decisiones: if / elif / else y lógica and · or · not
  • Ciclos for y while, con range()
  • Constantes y números mágicos (la sesión 06)
2do bimestre · énfasis aquí cae el peso

Lo que define este examen

  • Funciones: parámetros, return y alcance (scope)
  • Listas: recorrer, agregar, filtrar, ordenar
  • Diccionarios: claves, valores y .items()
  • Archivos: open / with, leer y escribir .txt y .csv
  • Excepciones: try / except / finally que no dejan caer el programa

La verdad incómoda: el examen final no pregunta «¿qué es una lista?». Te pide usar una lista de diccionarios, recorrerla con una función, guardarla en un archivo y atrapar el error cuando el archivo no existe — todo dentro del mismo problema. Por eso hoy practicamos integrando, no por piezas sueltas.

El banco de problemas.

Tres problemas tipo examen, cada uno integrando varios temas. Resuélvelos primero a solas. La solución de referencia está plegada bajo cada uno: ábrela apenas después de intentarlo —no antes—. No hay una sola forma correcta; compara la tuya con la mía.

Problema 1
funciones listas excepciones

El promedio que no se cae

Escribe una función promedio_seguro(numeros) que reciba una lista de calificaciones y devuelva su promedio. Debe sobrevivir a dos desastres: que la lista llegue vacía, y que alguien meta un dato que no es número. En ningún caso debe reventar: devuelve 0.0 cuando no hay datos y avisa de lo que ignora.

  • Una función con return de tipo float.
  • Recorrer la lista sumando solo lo que sea numérico.
  • Atrapar la lista vacía: división entre cero (ZeroDivisionError).
  • Atrapar valores no numéricos con try / except.
  • Probarla con al menos tres listas distintas.
enunciado.py
# Tu función debe comportarse así:
promedio_seguro([8, 9, 10])   # → 9.0
promedio_seguro([])           # → 0.0  (avisa: vacía)
promedio_seguro([7, "x", 9]) # → 8.0  (ignora "x")
Ver solución de referencia ábrela solo después de intentarlo
solucion_1.py
def promedio_seguro(numeros):
    # Sumamos solo los valores que sí son números
    suma = 0.0
    validos = 0
    for dato in numeros:
        try:
            suma += float(dato)
            validos += 1
        except (ValueError, TypeError):
            print(f"Aviso: ignoro el valor no numérico {dato!r}")

    try:
        return suma / validos
    except ZeroDivisionError:
        print("Aviso: no hay datos numéricos; devuelvo 0.0")
        return 0.0


# Tres pruebas exigidas
print(promedio_seguro([8, 9, 10]))   # 9.0
print(promedio_seguro([]))           # 0.0
print(promedio_seguro([7, "x", 9])) # 8.0
Problema 2
diccionarios listas funciones

El inventario que se ordena solo

Tienes una lista de diccionarios, cada uno un producto con nombre, precio y stock. Escribe dos funciones: una que devuelva el valor total del inventario (precio × stock, sumado), y otra que devuelva los productos ordenados del más caro al más barato, sin alterar la lista original.

  • Recorrer una lista de diccionarios con for.
  • Acceder a valores por clave: producto["precio"].
  • Una función valor_total(inv) que devuelva un número.
  • Usar sorted() con key= y reverse=True.
  • No modificar la lista original al ordenar.
enunciado.py
inventario = [
    {"nombre": "Café",  "precio": 85,  "stock": 12},
    {"nombre": "Taza",  "precio": 40,  "stock": 30},
    {"nombre": "Libro", "precio": 220, "stock": 5},
]
# valor_total(inventario)  → 3320
# mas_caros(inventario)[0] → el Libro
Ver solución de referencia ábrela solo después de intentarlo
solucion_2.py
def valor_total(inventario):
    # Suma precio * stock de cada producto
    total = 0
    for producto in inventario:
        total += producto["precio"] * producto["stock"]
    return total


def mas_caros(inventario):
    # sorted devuelve una lista NUEVA; no toca la original
    return sorted(inventario, key=lambda p: p["precio"], reverse=True)


inventario = [
    {"nombre": "Café",  "precio": 85,  "stock": 12},
    {"nombre": "Taza",  "precio": 40,  "stock": 30},
    {"nombre": "Libro", "precio": 220, "stock": 5},
]

print(f"Valor total: ${valor_total(inventario)}")  # $3320
for p in mas_caros(inventario):
    print(f"{p['nombre']:<8} ${p['precio']}")
Problema 3 · el integrador
archivos dicts try/except

La agenda que recuerda

Este es el problema más parecido al examen: lo toca todo. Una pequeña agenda de contactos guardada en un archivo .csv. Léela en una lista de diccionarios; si el archivo aún no existe, no truenes: empieza con la agenda vacía. Agrega un contacto y vuelve a guardarlo en disco conservando lo anterior.

  • Leer un .csv con open / with.
  • Atrapar FileNotFoundError en la primera corrida.
  • Cada renglón se vuelve un diccionario en una lista.
  • Una función para agregar y otra para guardar.
  • Volver a escribir el archivo sin perder lo anterior.
enunciado.txt
# contactos.csv (puede no existir aún)
nombre,telefono
Ana,5544001122
Luis,5588990011

# 1ª corrida: el archivo no existe →
#   no truena, agenda = []
Ver solución de referencia ábrela solo después de intentarlo
solucion_3.py
import csv

ARCHIVO = "contactos.csv"


def cargar_agenda():
    # Si el archivo no existe, devolvemos lista vacía
    try:
        with open(ARCHIVO, encoding="utf-8") as f:
            return list(csv.DictReader(f))
    except FileNotFoundError:
        print("No hay agenda previa; empiezo vacía.")
        return []


def agregar(agenda, nombre, telefono):
    agenda.append({"nombre": nombre, "telefono": telefono})


def guardar(agenda):
    with open(ARCHIVO, "w", newline="", encoding="utf-8") as f:
        escritor = csv.DictWriter(f, fieldnames=["nombre", "telefono"])
        escritor.writeheader()
        escritor.writerows(agenda)


agenda = cargar_agenda()
agregar(agenda, "Ana", "5544001122")
guardar(agenda)
print(f"Agenda con {len(agenda)} contacto(s) guardada.")

minutos en clase

El examen final no se trata de recordar la sintaxis exacta de memoria: se trata de pensar el problema, descomponerlo y escribir código que corra. Hazlo con este ritual en tres pasos —el mismo que usarás el día del examen:

1

Lee y descompón

Antes de teclear, escribe en comentarios # PASO 1, # PASO 2… el plan. Pensar primero ahorra el doble de tiempo después.

2

Escribe y corre

Resuelve paso por paso. Corre el programa seguido para cazar errores temprano —el hábito de debugging de la sesión 05.

3

Prueba los bordes

Pruébalo con datos raros: lista vacía, archivo ausente, texto donde se esperaba número. Si no truena, está bien hecho.

Tu carta

Tu repo, presentable.

Tu repositorio de GitHub es tu entregable del curso —y, llegado el día, tu primera carta de presentación profesional. Un buen repo se entiende en treinta segundos: estructura clara, nombres limpios y un README que cuente qué hay dentro. Hoy lo dejamos así.

└── sesion-26/     ← hoy
    ├── simulacro.py  # tu problema resuelto
    └── README.md     # qué hace y cómo correrlo

Anatomía de un buen README

  1. Título y una línea que diga qué es el proyecto.
  2. Descripción breve: qué problema resuelve y para qué sirve.
  3. Cómo correrlo: python simulacro.py y qué necesita.
  4. Ejemplo de uso: una captura o el texto de una corrida.
  5. Autor: tu nombre, grupo y ciclo 26-3.

Sí · esto da buena impresión

  • Nombres de carpeta consistentes: sesion-26, no Sesion 26 (final).
  • Commits con mensaje claro: "sesion-26: simulacro final".
  • Un README.md en la raíz que liste tus sesiones.
  • Código comentado y archivos .py que corren tal cual.

No · esto resta puntos

  • Archivos sueltos como final.py, final2.py, bueno_final.py.
  • Carpetas con espacios y mayúsculas mezcladas.
  • Subir capturas borrosas o código que no corre.
  • Un repo sin README: nadie sabe qué está mirando.

Criterios de evaluación

  1. Sin errores de sintaxis ni de ejecución — tu simulacro corre completo, de inicio a fin.
  2. Lógica correcta — resuelve de verdad el problema elegido, incluidos los casos borde.
  3. Funcionamiento óptimo — usa funciones y, según el problema, listas, diccionarios, archivos o excepciones.
  4. Autenticidad — tu propio código y tu propio README, no copiados de un compañero.
